Build a complete, working hackathon project called **WhatIf Graph — Graph-Powered AI Decision Simulator**, using FalkorDB as the core graph database.

**Goal:** Create an AI-powered web app that lets users simulate hypothetical changes to a software project or system and understand their downstream consequences using graph relationships.

**Tech stack:**
- Frontend: React, TypeScript, Tailwind CSS
- Backend: Python FastAPI
- Graph database: FalkorDB using its official Python client
- Graph queries: Cypher
- Use environment variables for database credentials and API keys.

**Core features:**

1. **Premium UI:** Create a polished, responsive dark dashboard with violet/blue accents, an interactive dependency graph, modern cards, smooth transitions, and a professional SaaS design. Avoid a generic template look.

2. **Demo graph:** Create a sample e-commerce system with nodes representing Payment Service, Order Service, Inventory Service, Notification Service, Database, Engineering Team, and Deployment Deadline. Add meaningful relationships such as DEPENDS_ON, OWNED_BY, and BLOCKS.

3. **Graph visualization:** Show nodes and edges visually. Users should be able to select a node and inspect its connections.

4. **What-if simulator:** Provide a text input and suggested scenarios:
   - What happens if the Payment Service goes down?
   - What if the database is delayed by two days?
   - What if the Engineering Team loses one member?
   - What if the Inventory Service is unavailable?

5. **Real graph reasoning:** Store the sample graph in FalkorDB. Use actual Cypher queries and multi-hop graph traversal to identify affected downstream components. Do not hardcode every scenario's result. Calculate impact from the graph structure and dependency relationships.

6. **Impact report:** Show the affected nodes, severity, dependency paths, potential bottlenecks, and recommended mitigation steps. Clearly distinguish graph-derived facts from heuristic recommendations.

7. **Baseline safety:** Run hypothetical simulations without permanently modifying the baseline graph. Display the original state alongside the simulated impact.

8. **Comparison:** Show baseline versus hypothetical scenario, number of affected components, risk level, and a clear explanation of why each component is affected.

9. **Reliability:** Add loading states, input validation, readable error messages, and a database connection status indicator.

10. **Documentation:** Write a detailed README covering the architecture, setup instructions, environment variables, FalkorDB configuration, graph data model, sample Cypher queries, and how to run the app locally.

**Implementation requirements:**
- Build functional frontend and backend code, not just mockups.
- Use FalkorDB for actual graph storage and queries.
- If credentials are missing, provide a clearly labeled demo mode with a local graph implementation, but never claim that FalkorDB was connected when it was not.
- Keep the application runnable and include exact startup commands.
- Do not leave core features as TODOs.
